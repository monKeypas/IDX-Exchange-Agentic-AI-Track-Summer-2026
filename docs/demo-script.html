Live Demo Script

Eight messages · five minutes · IDX Multi-Agent Real Estate Assistant

OPEN0:00 — 0:30

This is a WhatsApp interface over two MLS tables. rets_property is active listings, about 35,000 rows. california_sold is closed sales, about 87,000.

Messages come in through a single handler. A classifier assigns an intent, and that dispatches to one of seven agents — property search, market stats, semantic search, recommendations, RAG, and two for email. A mixed intent runs two agents concurrently and merges the output.

I'll run eight messages through it. The last two are the email path, which requires explicit approval.

Diagram on screen, not narrated. Switch to WhatsApp.

Find me affordable homes in Pasadena and tell me whether prices are rising

intent mixed → propertySearchAgent + marketStatsAgent, concurrenttables: rets_property + california_soldshows: multi-agent orchestration · NL property search · market analytics

While it runs

The routing is deterministic — pattern matching, not a model. Six word lists, and the first rule that matches wins. It costs nothing per message and every route is pinned by a unit test.

When it replies

That classified as a mixed intent — the search pattern and the market pattern both matched. Property search and market stats ran concurrently, listings from rets_property, medians and days-on-market from california_sold, and the two replies merged. 277 active listings in Pasadena, median close $1.57 million, average DOM 37 days.

42:10

Send

fully renovated with a chef's kitchen and open floor plan

intent semantic → semanticSearchAgentsource: L_Remarks embedding cache (384-d, MiniLM)shows: semantic similarity search

While it runs

Ahead of time, every listing was flattened into a paragraph — type, city, beds, baths, square footage, price, then the agent's written remarks — run through MiniLM, and averaged down to 384 numbers. That's cached on disk, which is why this comes back instantly.

When it replies

Nothing in that string maps to a column, so it routes to semantic rather than structured search. The query is embedded with MiniLM into 384 dimensions and ranked against pre-computed listing vectors by cosine similarity. Top five, scoring 55 to 59 percent.

~25s if the model is cold. Warm it beforehand.

52:45

Send

I like the first one, find similar homes

intent recommend → recommendationAgenttables: rets_property (candidates) + california_sold (comps)shows: recommendation engine · comp-validated pricing

While it runs

The structured half is graded: 20 points for a price within fifty thousand, 15 for matching bedrooms, 15 for the same city, 10 for size within three hundred square feet. Cosine similarity on the descriptions contributes up to 40 more.

When it replies

"The first one" resolves against the results from the previous turn. It then scores every other active listing — roughly 60 points structured, from price proximity, bedroom match, city match and square footage, and 40 from cosine similarity on the descriptions. The comp check pulls closed sales in the same city within 20 percent square footage over six months.

Send

What does DOM mean?

intent knowledge → ragAgentsource: 21 indexed chunks from knowledge/*.mdshows: RAG knowledge assistant

While it runs

Five markdown files, about fifteen thousand characters, sliced into 21 chunks of roughly 900 characters each — overlapping by 120, so a definition landing on a boundary isn't cut in half.

When it replies

Knowledge intent, so RAG. The question is embedded, the four nearest document chunks are retrieved by cosine, and generation is constrained to those chunks. The sources line lists which files they came from.

Send

Draft an email to me@example.com about Pasadena listings

intent email → emailDraftAgenttable: rets_property → draft queue (status pending_approval)shows: email drafting — the draft half of the approval gate

While it runs

Every value in that email is either fixed template text or a number read from the database. Nothing in it is generated, so a draft can't invent a listing or a price.

When it replies

The draft is written and persisted with a UUID and a status of pending_approval. Nothing has been sent. Drafting and sending are separate functions — the send function calls assertSendAllowed first, which throws unless explicit approval is passed in. No scheduled or background path reaches it.

Pause here before sending message 8. Requires a named recipient or nothing is queued.
